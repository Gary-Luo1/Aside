# I am Fine 产品介绍文稿（抖音 + 小红书 · 展示作品向）

> 用途：抖音 + 小红书竖版短视频（50–60 秒）的口播稿与字幕分镜底稿，也是后续 Excalidraw 产品介绍图的文字内容来源。
> 受众：非技术读者。语言要求：不提 API、密钥、模型名等技术词。
> 目标：作品展示 + 涨粉。结尾引导关注和评论，不贴安装教程。

## 一、视频口播稿（逐字，含时间轴）

**[0:00–0:03] 开场钩子**

> 读技术教程时，你最烦的是不是——一个看不懂的词，卡你半天？

**[0:03–0:15] 痛点重现**

> 以前我是这么干的：复制名词，切到搜索或 AI，再补一句「请用大白话解释」，然后切回教程……刚才读到哪了？忘了。名词一多，干脆就不读了。

**[0:15–0:25] 是什么**

> 后来我给自己做了个 Chrome 浏览器插件，叫 I am Fine。在教程里选中看不懂的词，旁边就会出现一个「解释这个词」的按钮。

**[0:25–0:40] 核心演示**

> 点一下，弹出两层解释。比如选中「幂等性」——专业解释：对同一操作重复执行多次，结果与执行一次相同；通俗解释：同一个请求发十遍，效果和发一遍一样，不会重复扣钱。不用离开页面，看完继续读。

**[0:40–0:48] 隐私承诺**

> 它只把你选中的那一个词，发给你自己选的 AI 服务。周围段落、页面标题、网址，它都不读。

**[0:48–1:00] 个人视角 + 收尾**

> 这是我自己被教程卡出来的小工具，现在正在小范围试用。关注我，以后多分享我自己做的效率小工具。你读教程时最常被哪个词卡住？评论区告诉我。

全文约 300 字，按正常口播语速（每分钟 280–320 字）约 55–60 秒。

## 四、发布前检查清单（红线）

- [ ] 全文无「API」「密钥」「模型名」等技术词，非技术读者能看懂
- [ ] 无「最」「第一」等极限词；不做「绝对安全」「什么都能解释」的承诺
- [ ] 提到「目前支持电脑上的 Chrome 浏览器」，避免手机用户安装失败后差评
- [ ] 录屏中不出现真实密钥、个人账号等敏感信息
- [ ] 不加微信号等导流信息，互动引导放在评论区
- [ ] 隐私表述只说「只发送选中的词」，不夸张
